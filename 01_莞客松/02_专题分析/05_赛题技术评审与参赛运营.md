## 2. 后版赛道与交付要求，属于方案记录

### 2.1 赛道一：互动空间与轻量小游戏

方案强调简单玩法、互动反馈、创意、情绪叙事、视觉与传播，优先做一个真正可玩且愿意重复尝试的核心机制。

| 要求 | 后版记录 | 复办需要确认 |
|---|---|---|
| 开发工具 | 文档顶部备注“不限制开发工具”，可使用 Vibe Coding 等 AI 辅助 | 官方当前工具、素材与平台边界 |
| 体验形态 | 可体验小游戏，关注核心玩法与传播 | 浏览器、手机、抖音平台或其他入口的正式要求 |
| 初赛包体 | Demo 控制在 8MB 以内；完整游戏可更大，复赛可扩展 | 文件类型、压缩方式、计量方法与上传校验 |
| 作品数量 | 后版写允许提交多个作品 | 个人/团队可多投的范围、是否能跨赛道、获奖占位规则 |
| 平台承接 | 顶部备注需上传抖音虚拟创作平台并提前申请 | 申请时间、账号、审核周期、现场备用方案 |

不能把“网页能运行”自动等同于“官方平台能接收”。赛前至少让一位测试选手按真实流程完成申请、打包、上传、打开和回执确认。

### 2.2 赛道四：视觉搜索与 VLM

方案要求面向具体用户和视觉场景，图片为核心输入，可结合视频、语音或文本，形成视觉理解、分析、搜索或匹配功能。内嵌截图进一步要求具备视觉理解能力的 AI Agent、清晰交互入口、评委可直接发起请求并体验核心能力。

建议用以下链路验收：用户触发 → 图片/视频等输入 → VLM 处理 → 结构化输出 → 匹配/建议/操作结果。此链路是复办检查方法，具体赛题仍需官方确认。

- 明确目标用户、出现问题的时刻和为何需要视觉信息。
- 提供真实或可合法使用的输入样例，说明依赖的内容库、商品库或其他数据。
- 清楚说明 VLM 在哪里发挥作用，避免只有文字包装、实际未用视觉理解。
- 提供可访问界面、账号或链接，让评委能自主触发。
- 现场网络或外部接口有依赖时，提前提交录屏、输入样例和运行说明。
- 不把后续完整商业链路列为本次已经完成的功能。

## 4. 评审链路与权限

后版文字及官方截图记录的流程为：

1. 社长/组织者将评委加入评审群，由抖音校园同学开通评审文档编辑权限。
2. 评委基于选手材料完成初评。
3. 评委逛游园会，对各作品真实体验并修正判断；各赛道提出 5 个提名获奖作品。截图以单赛道约 25 至 30 件作品举例，提名比例约 1:5 至 1:6。
4. 汇总所有提名作品，评委合议形成初步一、二、三等奖。
5. 抖音校园负责同学或赛道对应业务同学最终调整和确认。
6. 另统计选手投票与大众观众投票。

“每位提名 5 件”是截图示例，作品少的场次应提前确认数量，不能机械让评委提名超过该赛道作品数。分数支持初评与判断，最终名单依赖合议和官方确认，单纯算平均分不等于完成后版规则。

| 评审交付 | 责任与权限 | 复办验收标准 |
|---|---|---|
| 作品主表 | 选手运营收口，技术维护 | 项目编号、赛道、团队、Demo、材料、提交时间唯一 |
| 评委材料访问 | 官方数据管理员与技术 | 每位评委实际账号可打开、可写入测试，不仅群里说“开好” |
| 初评分/评语 | 各评委 | 同赛道同标准，完成覆盖记录；缺评清单可见 |
| 提名表 | 各评委提交，评审组整理 | 带赛道、编号和理由；不能以队名近似匹配误计 |
| 合议记录 | 评审负责人 | 候选、讨论结论、调整理由及回避事项留档 |
| 官方批准名单 | 官方确认人 | 具体版本与明确同意记录，冻结后进入颁奖稿 |
| 投票结果 | 计票人员、复核人 | 区分观众与选手票，截止和计票照片可追溯 |
| 颁奖与通知 | 总控、主持、选手运营 | 名称和奖项双人核对，现场荣誉与后续晋级分开告知 |

嘉宾评审群的历史任务为 4 月 10 日前建立嘉宾、导师、评审 A/B 邀请池。缺少完整最终名单意味着复盘不能自动用策划的“3 至 5 名评委”“3 名导师”报实际到场数量。历史沟通依据（不附原始对话）。

### 5.2 投票

后版计划青年共鸣奖由选手之间投票，按队伍发贴纸；游园会之星由大众观众贴纸投票。通用城市执行方案写每位游客 3 票，不可重复投给同一产品。选手每队票数、能否自投、同票处理、是否允许同时获多个奖，资料没有统一定稿。

复办建议：

- 用不同颜色区分选手与观众，提前公开一人/一队票数。
- 发票时登记发放身份，不能重复排队领票。
- 明确自投、重复投票、无效票、同票与截止处理。
- 所有展位用统一编号和票位，计票时间统一，至少两人核对。
- 观众进场时机与展位曝光尽量均衡，避免位置、朋友数量和进场时间变成主要决定因素。

投票奖衡量共鸣与传播，技术质量和获奖价值另由评委判断。若把人气票直接代入技术总分，机制就会鼓励拉人和攒票；本批后版方案没有要求这样合并。

### 5.3 晋级

后版官方截图写各赛道第一名保证晋级，其余不保证；晋级由抖音校园团队赛后确认，赛后一周内单独通知，现场不公布。该保证与正文仍写“具体名额待确认”并存，因此复办应取得当次官方批准后再承诺。持 PASS 卡也仍须完成官方报名及档案，不可把地方荣誉、PASS 卡、晋级和全国总决赛资格混为同一种权益。

## 6. 从招募到到场的运营链路

历史后版设计：飞书通知群 → 官方基础报名和选手档案 → 东莞站报名与筛选 → 本场选手群 → 入场确认 → 现场开发、展示及提交。城市交流赛是可选线下实践环节，不能替代官方基础报名。

| 环节 | 建议动作 | 必须有的记录 |
|---|---|---|
| 触达 | 记录高校/社群、联系人、实际发布时间、素材版本和报名入口 | 渠道台账与转化记录，不能只记“联系了校领导” |
| 基础报名 | 检查官方账号、通知群和档案完成状态 | 可核验标识，避免重复报名误计人数 |
| 城市申请 | 按资格、参赛意向、投入时间和场地容量筛选 | 录取与候补、拒绝原因口径、通知状态 |
| 组队 | 给个人报名者找队友渠道；记录联系人、成员、赛道、缺口 | 正式队伍确认和唯一队号 |
| 行前确认 | 到场、餐饮、过夜、特殊需求、行程及设备 | 已确认、未回复、退出分别统计 |
| 签到 | 核对身份、队号、赛道与物资包；异常台承接 | 真实到场人和队数，与保险、餐饮同步 |
| 开发跟进 | 每队给出核心闭环和实际阻塞，安排导师 | 项目状态、技术报障及辅导建议 |
| 提交 | 回执、链接、权限、编号、材料与截止状态 | 已提交、缺材料、失败、逾期分别记录 |
| 展示评审 | 每队展位和演示人，评委覆盖完整 | 体验、提名、合议与投票数据 |
| 赛后 | 发结果、作品回顾及后续联系 | 通知收悉、授权范围、项目持续状态 |

莞客松组队信息表（参考原资料未附）保留 10 条找队友记录，字段为发起背景、技术、项目需求、联系方式等。它是组队意向池，无法证明 10 支正式队伍或 10 名真实到场选手；也缺少清晰的队号、成员名单、赛道确认和参赛状态。AdventureX 的同类表属于其他赛事参考。

## 8. 技术保障从“设备”转成完整用户链路

历史里赛题、提交、网络、投影、音响和评分均由技术线承担，若只安排一位技术同学，很容易在开幕播放、现场报障、评分故障同时发生时冲突。应根据高峰并发安排技术主岗和替补。

| 技术对象 | 赛前需要确认 | 现场验收 |
|---|---|---|
| 网络 | 用户/设备峰值、场地 IT、模型与工具访问、备用方式 | 同时访问、上传、Demo 和评分的实际测试记录；无实测不报网速 |
| 电力 | 每桌及展位设备、线缆路径、专业布线、保护、容量 | 电工及场地方确认；不靠排插数量推断供电能力 |
| 模型/工具资源 | 账号申请、访问、用量、费用承担、有效期与限制 | 首位测试选手真正调用成功，异常与余额可追踪 |
| 作品提交 | 官方平台、本地备份、格式与大小、权限 | 实际提交和修改测试，故障保留时间及材料 |
| 评审 | 评委账号、填写权限、导出冻结与备份 | 每位评委完成测试；同赛道作品一致可见 |
| 舞台 | 全部文件、字体、比例、转接头、音频、计时与切换 | 实机完整彩排，离线副本、备用串词和静态画面 |
| 影像 | 云相册容量、文件传输、实时照片、闭幕快剪 | 可上传、可播放、可下载；源文件与发布稿分开 |

后版顶部出现 TRAE Pro Mode 资源及“4 月 30 日前发”的备注，没有完整兑换码数量、领取名单与生效证明。复盘可保留该待办，不能写成每名选手已经获得权益。云空间 5 月 3 日满额也提示素材与工作文档需要容量验收。历史沟通依据（不附原始对话）。

## 9. 下一场应该测什么

下面为建议的指标，不是对本次补造统计。

| 指标 | 定义 | 用途 |
|---|---|---|
| 有效报名 | 资格与档案完成的独立申请人数 | 区分内容曝光和可录取人数 |
| 录取确认率 | 明确确认到场人数 / 已录取人数 | 提前决定补录、餐饮、保险与床位 |
| 实际到场率 | 签到人数 / 确认人数 | 判断行前运营，须解释退出与缺席 |
| 队伍形成率 | 正式队伍人数 / 到场人数 | 判断找队友与组队服务 |
| 合格提交率 | 满足最终材料和截止规则的项目 / 实际队伍 | 判断规则、培训和技术支持 |
| 可体验率 | 评委能现场触发核心功能项目 / 提交项目 | 判断交付真实性 |
| 评审覆盖 | 每个项目被各评委体验/初评/提名的状态 | 发现漏评与不均衡 |
| 技术故障 | 数量、影响队伍、持续时长及处置 | 定位网络、权限、平台或资源瓶颈 |
| 赛后存活 | 指定时间后仍可打开的 Demo、继续迭代团队 | 检验作品和社群资产，勿只看照片数量 |

5 月 20 日反馈学校宣传参与人数少、临近活动专业能力不足、临时通知和现场设备效果差。这些提供改进方向，尚不足以量化宣发转化、故障损失或选手满意度。下一场从报名、签到、提交和评审链预埋记录，才能判断哪些改进真正有效。
